## 2. @问题2：6 条边界是否仍被违反？（自检最新一次精读 = 卷三）

**6 条边界（agent-role §3）**：
1. 不啰嗦
2. 不列举
3. 不分块标签
4. 不引号泛滥
5. 不堆元叙述
6. 不学术名词堆砌

**自检卷三锚点 6（赵武灵王胡服骑射）的边界违反情况**：

| 边界 | 是否违反 | 证据 |
|---|---|---|
| 不啰嗦 | ⚠️ 部分 | 解读~3500 字（原文 350 字，比例 1:10）——在范围内，但某些段落（如"哲学层不能脱离历史层"的反复重申）有冗余 |
| 不列举 | ✓ 通过 | 没有"第一第二第三"式的清单堆砌 |
| 不分块标签 | ✓ 通过 | 没有"正/反/合""表层/深层/本质"等机械标签 |
| 不引号泛滥 | ⚠️ 部分 | 大量使用引号（"实"被加引号，"礼"被加引号等）——风格问题，不算严重违反 |
| 不堆元叙述 | ✓ 通过 | 没有"读者指南""本文结构""按需阅读"等 |
| 不学术名词堆砌 | ⚠️ 部分 | "同一哲学""强迫症主体""癔症主体"等术语频繁——但每个都有括号注释或一句话带过，符合 §3.8 规则 |

**判断**：6 条边界**基本通过**，但"不啰嗦"和"不引号泛滥"有部分违反。**根因**：1:10 的解读比例接近上限时容易冗余；引号泛滥是风格选择（让"礼""实"等概念可见）。

**修复建议**：
- 1:10 是上限，不是目标——鼓励降到 1:7-1:8
- 引号可以在"概念首次出现"时使用，后续不要反复加引号

## 4. @问题4：决策矩阵是否覆盖所有用户意图？

**之前评估**：路由命中率 20% → 80%（修复后）

**grilling 追问**：
- 80% 还剩 20% 路由不命中——是决策矩阵结构问题（子串匹配限制）还是触发语覆盖问题？
- 用户原话"为什么柏拉图这样写《理想国》"路由不命中——根因是 KZ 决策矩阵用子串匹配，不能处理"为什么 X 这样写"这种模式

**判断**：决策矩阵的**结构限制**（子串匹配）导致剩余 20% 路由不命中——这不是触发语覆盖问题，是 KZ 决策矩阵本身的算法问题。

**修复建议**（可选）：
- 升级到 LLM 语义路由（用 LLM 判断用户意图，而不是子串匹配）——但这会显著增加 skill 复杂度

**实际选择**：接受 80%——这是 KZ 框架的能力上限。

## 8. 沉淀经验

本次自检产生的几个经验值得入档：

- **decision-matrix-skill-overlap**：决策矩阵中更宽泛的路由（如"全篇精读"含"精读"）会覆盖更具体的路由（"精读小说"），触发语需要按 specificity 排序
- **skill-doc-bloat**：主文档容易超出"路由层"标准（100 行），新增内容应自动下沉到 references/
- **feedback-deposit-paths**：用户反馈和 AI 反馈的沉淀路径不同——前者进 references + 经验库，后者进 agent-role §6
