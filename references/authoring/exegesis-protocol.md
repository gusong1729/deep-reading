# 难段深度解读协议(Exegesis Protocol)

> 用户明确需求(2026-08-22):精读的灵魂不是结构化定义,而是**把难懂段落讲成人话**。本协议定义"遇到难段怎么解读"。

## 定位

当用户指出某段难懂内容时,基于**上下文**把这段解释清楚--它在讲什么、为什么在这里、涉及什么概念。适用**全部方向**(哲学/古文/电工/其他)。

## 触发(手动,不自动)

用户主动说:"这段看不懂""解释一下这段""这段什么意思"。**不做自动检测**,等用户指令。

## 输出格式(强制)

```
【原文】
(原样复制段落,保持原文排版,不改写不节选)

【解读】——以多段大块论文式论述展开,总篇幅远大于原文(推荐比例 1:5 到 1:10 以上)
  1. 论述角度一……
  2. 论述角度二……
  3. 论述角度三……
  4. 学术争议与边界……
  5. 收束……
```

**铁律：绝不允许一段原文只配一段等长解读的“定义式”轻量做法**。一段原文必须配**好几段大块解读**。论述必须以论文式短文形式展开，不是“要点说明”。

## 解读结构（四步，视情况合并）

> **深度标准**：解读要像学术专著段落——**大片大片的具体内容**（Agent.md §2）。单段难点解读通常不少于 500 字，复杂段落可上千字，直至讲透。禁止“要点式”压缩。

1. **这段话在讲什么**——基于上下文的白话转述：不逐字翻译，讲清这段要表达的核心意思（用用户能懂的话）
2. **上下文关联**——这段为什么出现在这里：承接前文什么、为后文埋伏什么、在整章/整篇中承担什么功能
3. **概念溯源**——段中关键术语的来龙去脉（演变、出处、学界争议），但**必须结合本段语境**：讲“这个概念在这里怎么用”，不是发孤立的概念百科
4. **人话总结**——一句话收束这段的意思，让用户能用自己的话复述

每步都要**展开写**：引用原文关键词句、重建论证逻辑（前提→推理→结论）、呈现学者分歧，像写书一样分层铺开。

## 铁律

1. **必须看上下文**:解读不能脱离前后文。若上下文不完整、无法确证含义,先说明"依据当前上下文,这段话的解读是......,但完整把握需要前后文",再解读。
2. **禁止"直觉类比"**:哲学与理论文本**不允许**"打个比方你就懂了"式的直觉抓取。要讲就讲清逻辑、概念与论证;类比最多作为辅助说明且必须标注"这只是辅助",不得替代概念解释。
3. **概念溯源不脱离本段**:溯源服务于理解本段,不是顺带发表概念百科。
4. **原文完整复制**:不改写原文、不以关键词句代替整段(段落超长可节选但须注明"节选")。
5. **可消化性**:解读的标准是--用户读完能用自己的话复述这一段;若做不到,说明解读不到位,继续拆。

## 落库

解读成果**写回 readings/ 精读页**对应位置(该文已有精读页时),格式:

```markdown
### 难段解读:〈段落主题〉

> **原文**:......
>
> **解读**:......
```

同时在对话中完整呈现。无精读页的文章,解读暂存对话,用户决定是否建精读页。

## 方向补充规则

- **古文**:先解决句读与字义(训诂优先),再讲上下文;白话转述须对应原文句序。
- **电工/技术**:难段多为公式推导--解读"这一步为什么这么推"的逻辑链,概念溯源指向基础原理与国标。
- **哲学**:完整执行四步;概念溯源是重点(术语演变+学界分歧),但始终服务于本段。
